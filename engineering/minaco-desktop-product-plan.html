01

产品定位：你的 Agent 工作台

沿用 Minaco 品牌与 “Think with you. Act for you.”，新增独立下载的桌面 Agent 工作台。现有 AI cofounder workspace 继续运营；两条产品线共用身份与支付基础设施，桌面第一版聚焦个人。

FOR WHOM

独立开发者与一人公司

同时做研发、调研、内容和运营，已经在多个助手之间切换，希望每项工作选合适的 Agent，而不重复组织资料和上下文。

CORE PROMISE

选 Agent，接着做事

只安装 Minaco；一个订阅使用所有已接入的 Agent。不同对话可选择不同 Agent，同一对话也能切换；Minaco 将可见上下文交给新的原生 Agent 后继续显示在同一条对话中。

WHY MINACO

连续的工作资产

会话、文件、结论、来源和待办共同构成项目资产。聚合入口服务于任务连续性；模型调用、插件兼容和费用都能解释。

核心场景用户得到的结果成功判断
研究 → 开发同一对话先用 Claude 整理方案，再切换 Codex 实现新 Agent 获得截至切换点的可见上下文与文件版本，界面仍是一条连续对话
不同 Agent 并行工作Kimi 调研、Codex 开发，分属不同会话与执行环境状态与费用分别可见，共享文件写入不会静默冲突
需要确认的本地操作知道谁要改哪些文件或执行什么命令，并能批准或拒绝选择真正传回原生引擎；拒绝后操作未发生
中断后继续关闭窗口或重启后找到原会话，知道能否恢复区分历史可查看、引擎可续聊与正在执行，避免虚假“继续”
产品边界：“Agent”指带有原生规划、工具、上下文管理的运行时；“模型”是它调用的推理服务。UI 分别展示两者。跨 Agent 交接不承诺恢复另一家引擎的隐藏状态或完全复刻原厂桌面客户端。

05

一个对话，可由多个原生 Agent 接力

用户看到的 Minaco Conversation 是持续工作单元；内部由按时间排列的 AgentSegment 组成。每个 segment 固定绑定一家 provider、一个 Paseo Agent 和一个原生会话标识。切换 Agent 会结束当前 segment、创建目标 segment 并注入可移植上下文，不篡改任何厂商原生 session。

对象职责不变量
Project资料、目录、项目记忆、成果归属跨设备用 projectId 对应各自路径；绝对路径不直接当云端身份
Conversation用户看到的一条持续对话，包含一个或多个 AgentSegment切换 Agent 不改变 conversationId；历史按 segment 保留来源
AgentSegment绑定 provider / Paseo agentId / nativeSessionId 的一段执行一个 segment 只属于一家 Agent；不同引擎不得复用原生会话标识
Run一次用户触发的执行；包括审批等待、模型/工具往返默认同一会话只允许一个活跃 Run；后续输入排队或使用已验证的 steer
Artifact / ContextRef文件成果与可追溯的上下文引用记录来源会话、内容哈希、时间与版本，接收方知道看到的是哪个快照
ContextEnvelope携带可见对话、目标、决定、约束、待办和带哈希的成果引用不复制隐藏推理、厂商凭证、临时进程状态或历史授权

用户说的“跨 session”，分别落到四项能力

A · REFERENCE / D0

引用已有会话

选定消息、结论和文件加入当前任务。引用带来源与版本；默认不把用户所有历史注入每一轮。引用范围在发送前可查看。

B · HANDOFF / D0

同一对话换 Agent

自动生成交接包：可见对话、目标、已完成项、未完成项、约束、证据和文件引用。目标引擎以新的原生 session 开始，Minaco 把它作为同一 Conversation 的下一段展示。

C · DELEGATE / M1

委派与结果回流

父会话通过本地 Host 创建有范围的子任务，关联 parentRunId。子任务独立预算、权限与目录；完成后以结果引用返回。调度留在本机，并限制嵌套深度与并发。

D · MEMORY / M1

共享项目知识

共享经确认的事实、偏好和决策。保留来源、更新时间、撤销/删除入口。长期记忆是显式知识层，不能代替完整原生会话状态。

会话生命周期与并行写入约束

Session 状态：ACTIVE / ARCHIVED / DELETED；可恢复性单独存为 READY / NEEDS_ENGINE / INCOMPATIBLE / HISTORY_ONLY。归档只是隐藏，删除需明确本地记录、备份与项目文件的各自处理范围，不联动删除用户原始项目目录。

同一项目允许多个会话并行，但代码写入默认各用 Git worktree；普通文档任务采用独立产物目录并在合并时检查哈希。对于可以任意访问文件系统的原生 Shell，应用层“文件锁”只能协调受控入口，不能当作系统沙箱。没有原生隔离时，提供串行写入模式，不能宣传强隔离。

跨设备续接只迁移可序列化状态与文件快照，不迁移活着的终端、浏览器页面或待处理系统弹窗。目标设备重新解析本地路径与凭证，取得执行租约后启动。

Run 状态与界面必须一致

PREPARING → RUNNING校验引擎、工作区、额度，启动执行
WAITING_APPROVAL暂停受控操作；展示确认范围及超时
CANCELLING → CANCELLED先停止请求与工具，再确认取消完成
COMPLETED / FAILED原生终态落盘；账单结算另行追踪

断线时显示 RECONNECTING；进程状态不确定时进入 NEEDS_RECOVERY。拒绝某次工具调用可能让 Agent 改用其他方法，不应自动把整轮标为失败。结算状态 PENDING / SETTLED / REVIEW 与执行终态正交。

Paseo 的单个 Agent session 固定 provider；其 fork-context 和 chat_history 附件可直接作为交接基础。Minaco 需要新增逻辑 Conversation / AgentSegment 映射和跨 session ContextEnvelope，不能把 Paseo 的 fork 标签直接当成完整产品语义。

07

插件与权限：统一入口，准确保留语义

扩展类型管理方式兼容策略
通用 Skills一个 Minaco 技能目录，生成各引擎可读的配置/安装映射检查格式、工具依赖、上下文注入规则；文本可复用不代表执行结果相同
MCP 工具集中登记服务、工具、账户与作用域按引擎生成 stdio/HTTP 配置；协议和认证不兼容时标记不可用
原生插件与 Hooks保留各家 manifest、版本与生命周期安装在隔离的 engine home；不把同名 hook 跨引擎直接复用
浏览器 / 电脑操作本地组件、浏览器扩展和系统权限独立检查声明是否支持真实浏览器登录态、独占鼠标、前台要求和操作系统限制

AGENT POLICY

工具执行确认

引擎发出请求；Host 记录并交给 UI；用户选择映射回原生批准选项。没有回调的自动执行路径不得假装经过 Minaco 审批。

OPERATING SYSTEM

设备授权

文件目录、屏幕录制、辅助功能、通知等由系统控制。Minaco 展示状态并引导，不能用聊天里的“同意”取代系统授权。

SERVICE ACCOUNT

外部账号连接

邮箱、网盘等按用户授权。模型网关统一付款不等于统一获得用户的第三方数据权限；连接凭证与模型凭证分开管理。

一轮任务如何跨越前端、本地与云端

点击步骤查看消息流向。用户看到一个持续的任务；内部每次模型推理、工具执行与计费都有自己的标识，避免把“收到 HTTP 200”误认为整个任务已经完成。

  1. Renderer → Host：校验账户与项目，写入本地用户消息和 PREPARING Run。
  2. Host → Cloud API：按幂等键创建调用授权，校验模型和预算，获得 runGrant。
  3. Host → 原生引擎 → Relay → Gateway → 模型厂商；流按反方向返回。
  4. 原生引擎提出工具请求，必要时经 Host/UI 审批，结果回到原生循环。
  5. Host 先持久保存事件，再通知 UI；以原生终态判断成功、失败或中断。
  6. Gateway 结算调用，账本对账；已开启备份的会话上传一致性快照。
关键链路时序约束用户反馈
发送消息先持久建档，再请求准入；重复 clientRequestId 返回同一 Run准备中 → 执行中；额度拒绝不丢失草稿
流式响应Gateway 转发 SSE / 协议流；Host 按 seq 持久化并推送；UI 合并 delta增量文本与工具步骤；流断开显示重连而非完成
工具审批请求持久化 → 显示 → 决定校验 → 原生应答；执行在应答之后需操作的内容与范围；过期状态；可拒绝
停止Host interrupt；关闭当前请求，协调工具终止；记录仍无法确认的外部副作用“正在停止”后才显示“已停止”；停止不是撤销文件或已发送请求
结算真实上游用量为依据；客户端完成回报只作运行状态，不决定价格已完成 / 用量待结算可同时存在；无 usage 时显示待核对

桌面登录、账户切换与注销流程
  1. Host 生成 state 与 PKCE challenge，系统浏览器打开 Minaco 授权入口。已有用户沿用现有账号。
  2. 身份桥校验登录后生成一次性、短期、绑定 challenge 的 code；通过允许的应用链接返回。URL 不携带 access token。
  3. Host 以 verifier 换取设备凭证；服务端校验 redirect、state、一次性消费和有效期。这里是拟议的 Minaco 换票服务，不是假设 Clerk 已经提供了这套桌面流程。
  4. 切换账号前停止或明确结束旧账号任务、关闭子进程和 Relay，清空 UI 缓存，切换本地库和凭证命名空间。
  5. 退出登录撤销当前设备 refresh credential；选择保留或删除本地历史。远程撤销阻止后续云端调用，不能保证抹除已下载到用户设备的内容。

请求和响应都经过网关

原生引擎在本地组装提示词、工具定义和上下文，经 Relay 发往 Minaco。网关替换鉴权后访问厂商，响应按原协议流式返回网关 → Relay → 引擎，再由引擎执行下一步本地操作。

客户端可被检查，计费不能信任它

用户掌控自己的电脑，平台凭证也可能被提取。安全目标是不给客户端供应商共享密钥；云端仍须限制平台凭证的作用域、并发与预算，并拒绝伪造的用量回报。

API 与订阅令牌分开验证：原厂消费者订阅的 OAuth 令牌可能绑定专用端点、账号权益与产品协议，不是任意 API 的通用密钥。Demo 优先使用支持自定义出口的 API/合作接入；平台订阅账户方案另列接入测试和厂家授权范围，不写成已解决能力。
13

统一支付：复用基础设施，明确产品权益

用户在 Minaco 购买和查看账单，网关记录各家实际调用。复用账号、Stripe 商户与支付逻辑，不自动等于共用原线上套餐额度。建议桌面有独立 SKU 和权益，避免影响现有线上用户；共享余额作为后续明确决策。

PURCHASE

平台收款与履约

复用支付入口、Checkout / Portal 经验与签名校验。购买必须携带服务端确认的 productScope=desktop 和现有用户映射。

METER

上游真实用量

一次任务可能多次请求。按供应商、模型、请求和重试分别记录输入、缓存、输出及其他计费项，保留计价版本。

EXPLAIN

可解释的桌面账单

展示任务消耗、引擎/模型、已结算和待结算。明确测试积分、平台积分与美元成本的区别，不把订阅百分比当固定 token 价格。

阶段后端处理幂等 / 异常处理
购买到账支付服务验证厂商事件 → 桌面产品路由 → 新库 PaymentInbox → 发放权益eventId 与发放业务键去重；不能凭浏览器跳转成功发额度
运行准入校验桌面权益、设备、模型和并发，原子预留任务预算，发 runGrant同一个 clientRequestId 不重复预留；过期授权拒绝后续调用
每次模型调用网关绑定 invocationId / attemptId；核查余额和预留，记录供应商 requestId同一 HTTP 请求去重与上游实际重复执行区分处理；不能只按 Run 去重费用
结算 / 释放根据上游 usage 计算扣减；任务结束且在途调用核清后释放剩余预留未知用量转 PENDING/REVIEW；不因客户端退出就记为零成本
退款 / 失效依据已确认支付状态更新后续可用权益，追加调整流水不覆盖原消费记录；支付与用量跨库用 outbox + 重试 + 对账
成本公式与预算执行口径
供应商调用成本 =
  非缓存输入量 × 对应输入价格
  + 缓存读取 / 写入量 × 各自价格
  + 输出量 × 对应输出价格
  + 按厂商规则计费的其他项目

任务成本 = Σ 该 Run 下真实发生的调用成本
平台消费 = 任务成本按当时费率规则换算的积分 / 货币金额
套餐权益 = 独立产品配置；不能用月费倒推固定 token 单价

不同厂商的 usage 字段并不等价，缓存或推理量可能已经包含在其他字段中。按各家的定义归一，避免重复相加。价格表记录币种、版本和生效时间，本规划不锁定具体售价。

要承诺硬预算，应在每次调用前按允许的最大输出及计费上界预留，并将并行请求计入。对于无法可靠取得上界的模式，只能标为“软预算提醒”，不能把停止下一次请求宣传成绝对不超支。取消流也不代表厂家没有产生费用。

复用时的兼容门槛：同一个 Stripe 商户的 webhook 可能把桌面产品事件送到现有处理器。上线前必须验证产品路由、未知 SKU 处理和幂等，确保不会给旧线上产品误发额度或重复履约。D0 使用测试支付环境，不修改现有线上余额。

建议默认：桌面权益在新库独立记账，原线上账本继续服务原产品；复用支付组件与身份桥。若最终选择共用钱包，则只由一个计费服务维护该余额，新库保留调用明细并通过幂等接口结算，禁止两边各存一份可写余额。

14

恢复、备份与发布：把边界变成可验证行为

本地优先意味着电脑负责执行，也意味着休眠、退出、文件变化都要有明确处理。云端备份负责找回资料，不自动承担运行中的原生进程。

情况预期行为实现约束
关闭窗口 / 退出应用关闭窗口可留在后台；真正退出时提示正在运行的任务，停止后保存窗口生命周期与 Host 进程区分；不能把“关闭窗口”直接视为任务完成
电脑睡眠 / 断网历史仍可查看；任务显示中断或待恢复；联网后检查原生状态不承诺后台云端续跑，不盲目重放已执行工具
原生引擎崩溃保留最后事件和产物；给出恢复或创建交接会话的入口原生 resume 成功才能标记可续聊；失败保留 HISTORY_ONLY
模型流中断保留部分结果，标记请求结果不确定；决定是否显式重试上游可能已计费；为新尝试生成 attemptId，避免重复工具副作用
文件路径变动 / 并行修改重新定位或显示版本冲突，不用备份直接覆盖新文件路径按设备解析；校验相对路径、符号链接和内容哈希
设备丢失 / 换电脑撤销旧设备，在新设备登录并选择恢复备份无备份则不能恢复；引擎版本、项目文件和外部账号均须重新校验
用量无法确认结果可见，费用显示待结算；后台补偿和对账预留与在途请求处理完成后才能释放；不能依赖桌面在线结算
历史备份的提交与恢复协议
  1. 用户选择是否开启备份及内容范围：会话文本、原生状态、所选产物分别说明；默认不上传整个项目目录。
  2. Host 在运行结束或经验证的一致性点生成快照。SQLite 使用一致性备份机制，不能只复制正在写入的主文件而遗漏 WAL；原生会话按引擎支持的方式导出或暂停后采集。
  3. 清单包含 schemaVersion、engineId/version、来源设备、文件哈希、父版本和所需组件；排除凭证、缓存、依赖目录和临时文件。
  4. 先上传不可变对象并验证哈希，再原子提交 manifest；半成品标为未完成，不出现在可恢复列表。失败可续传，不覆盖旧的有效版本。
  5. 恢复到新的暂存目录，验证所有者、大小、路径和哈希；兼容校验通过后切换本地索引。执行过迁移的状态先留副本，不能盲目交给旧版引擎。
  6. 多设备初期采用“导入为本地副本”，不自动合并两个原生会话历史。实时双向合并与设备租约属于 M2。

传输 TLS 与服务端加密存储属于 M1；端到端加密需要独立的设备密钥、恢复密钥和找回流程。未实现端到端加密之前，不能宣称平台无法读取备份。

独立发布与组件管理

桌面官网、安装包、桌面 API、网关分别发布和回滚；引擎目录固定兼容版本、平台架构与包哈希。签名/公证、组件来源和更新完整性纳入发布门槛。新版本失败回退时不破坏已有会话状态。

只记录必要的运营信息

默认记录 requestId、Run、引擎/模型版本、延迟、错误码和用量。请求正文只用于转发，不作网关日志；调试采样须显式开启并脱敏，且不得记录鉴权头。

质量指标建议验收口径
本地可用性断网可打开已保存历史；强制退出后已确认持久化的消息不丢失
界面响应固定测试机上，普通导航与输入反馈 p95 < 300 ms；模型首 token 延迟单独统计，不混入 UI 指标

备份可恢复性在另一台干净设备完成下载、校验、历史查看与支持引擎的续聊；只上传成功不算恢复通过
