# 海外付费 MVP 工程标准

目标是把一个清楚的产品想法，在已有基础设施和经过验证的模板上，用约 4 至 8 小时交付成带用户系统、运营后台、支付和托管地址的 Web MVP。默认容量是 100 个同时在线用户；重任务容量另行约定。

核心做法：**固定底座，生成业务，自动验收，携证据交付。** 每次只实现一个主要价值流程，让用户完成真实任务并付费。登录、账单、权限、部署、恢复和观测由底座提供。

这是基于 altselfs 代码形成的标准与实施契约，尚未实现为可运行的 starter 或一键生成器。现有产品也尚未通过本标准的 100 用户容量验收。

## 默认决策

| 项目 | 默认值 |
| --- | --- |
| 市场与语言 | 海外，英文界面，UTC 存储时间 |
| 应用 | Next.js App Router、TypeScript、React、Tailwind |
| 登录 | Clerk，邮箱和 Google；默认不加入手机号和组织协作 |
| 数据 | 一个产品一个托管 PostgreSQL 数据库，Prisma 管理业务模型 |
| 支付 | Stripe Checkout 和 Customer Portal，服务端权益表 |
| 托管 | Vercel 承载 Web 和短 API；轻量 Node worker 承载持久任务 |
| Worker 托管 | 复用现有 ACR、ECS、Docker 发布路径，按产品隔离配置和数据 |
| 文件 | 需要文件时复用 OSS 接入，私有桶和签名直传 |
| 管理后台 | 同一应用的 `/admin`，独立管理员权限及审计 |
| 业务范围 | 一个核心对象、一个核心流程、一个主收费方案 |
| 初始容量 | 100 在线用户；重任务默认目标 5 个执行槽，须压测后确认 |
| 基础架构 | 模块化单体及轻量 worker，按需增加 AI、浏览器和第三方连接器 |

这些是新项目的默认架构决策，不是 altselfs 当前部署配置的描述。复用托管方式不等于共享生产密钥、业务表或浏览器账号。

## 一次性底座与每次生成的业务

底座负责 `auth`、`billing`、`entitlements`、`jobs`、`storage`、`admin`、`observability`、`deployment`。业务负责用户输入、核心数据、处理逻辑、结果展示和价格表达。公共模块不依赖业务模型、页面或产品名称。

先把底座做成一个独立模板仓库，使用版本号固定依赖、迁移和验证记录。新项目从已验证版本实例化；积累两个真实产品后，再判断哪些部分值得抽成包。初期无需同时建设插件市场、代码生成平台和通用低代码引擎。

## 可以直接用于下一次产品任务的指令

> 按本目录的架构标准交付一个海外付费 Web MVP。先把我的想法转为产品契约，明确用户、核心结果、收费点和容量；能从描述推断的内容直接采用默认值。优先复用已验证底座，只生成业务模块。完成登录、数据隔离、运营后台、Stripe 支付履约、部署、真实浏览器流程与容量验证。交付线上地址、管理员入口、版本、证据、运行成本边界和恢复步骤。未配置、失败或未验证的能力必须如实标注；不能用演示数据或构建成功代替产品可用。

实际执行前应确认已经存在可运行底座。本目录本身只提供标准，不能代替模板代码和云资源。
